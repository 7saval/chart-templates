### 2. `homeVectorKpis` identity-churn 위험 점검 (버그 아님으로 결론)

## 🐛 발생한 문제 & 해결

### 문제 1: 15m 기본 기간에서 Adapter-CDC 등 바차트가 휑해 보임

- **원인**: mock `sparklineData`가 5분 간격 12포인트(55분 폭)인데 TopHeader 기본 기간이 15m라 2~3개 포인트만 걸림.
- **1차 시도(롤백됨)**: `stepMinutes`를 1분으로 줄이고 `MiniBarChart`에 `xAxis.min/max`를 `range`로 명시 고정. 15m/1H 전환까지는 잘 됐지만, 사용자가 "막대가 끝에 너무 작게 보인다"고 피드백해서 두 변경 모두 롤백.
- **최종 해결**: mock/차트는 그대로 두고 `App.tsx`의 기본 `timeUnit`을 `"1H"`로 변경. 기존 데이터 폭(55분)이 1H 안에 자연스럽게 다 들어옴.
- **참고**: `MiniBarChart`는 여전히 `xAxis.min/max`를 명시하지 않고 `data.filter()`만 하므로, 기간을 필터 폭보다 훨씬 넓게 선택하면(6H/1D 등) 차트가 시각적으로 거의 변화가 없다 — 이번엔 우선순위가 아니라서 그대로 둠.

### 문제 2: Storybook `Meta of={} must reference a CSF file module export or meta export`

- **원인**: 미확정. 관련 `.mdx`/`.stories.tsx` 파일 자체는 모두 정상이라 코드 문제는 아닌 것으로 보이며, 세션 내내 켜져 있던 Storybook dev 서버의 Vite 의존성 캐시/HMR이 잦은 라이브 편집(특히 편집→git checkout 롤백→재편집)으로 stale해졌을 가능성이 유력.

- **참고**: 재시작 후에도 재현되면 다음 세션에서 이어서 조사 필요.

## 💡 배운 점 / 메모

- echarts `xAxis: {type:'time'}`는 `min`/`max`를 명시하지 않으면 필터링된 데이터의 실제 extent에 auto-fit한다 — "선택 기간에 따라 차트가 달라져야 한다"는 요구는 `data.filter()`만으로는 부족하고 축 경계를 range로 명시 고정해야 하지만, 이번엔 사용자가 그 결과(막대가 구석에 작게 몰림)를 부자연스럽다고 느껴서 더 단순한 "기본값 변경"으로 방향을 틀었다 — 기술적으로 더 "정확한" 해법이 항상 최선은 아닐 수 있다.
- 같은 컴포넌트를 서로 다른 두 레이아웃(옆/아래)으로 써야 할 때는 variant 플래그로 조건부 클래스를 분기하되, 조건을 좁게 잡아서(`chartVariant==='bar'`일 때만) 기존 사용처가 영향받지 않게 해야 한다.
- `.pptx` 슬라이드가 편집 가능한 텍스트가 아니라 통짜 스크린샷 이미지로 박혀 있는 경우가 있다 — 이럴 땐 `extract-text` 대신 `zipfile`로 `ppt/media/imageN.png`를 직접 꺼내서 봐야 한다.
- Storybook 에러를 진단할 때는 먼저 관련 `.mdx`/`.stories` 파일 자체의 정합성(참조 오류, title 중복)을 코드로 확인하고, 문제가 없다면 Vite/Storybook 캐시 stale을 의심하는 순서가 효율적 — 특히 같은 세션에서 파일을 여러 번 편집/롤백했다면 그 가능성이 더 높아진다.
