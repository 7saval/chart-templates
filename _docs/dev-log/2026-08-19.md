### 2. "새로고침하면 다시 보인다" 버그 재현 및 근본 원인 규명

- Chrome 자동화 도구로 로컬 앱(`localhost:5175`)을 열어 5초 자동 갱신을 여러 사이클 지켜본 결과, Adapter-CDC와 Milvus(둘 다 `sparklineData` 보유) 노드가 **연결된 엣지와 함께 화면에서 완전히 사라지는 것**을 재현했다.
- `getComputedStyle(node).visibility`로 직접 확인해 React Flow(`@xyflow/react`)가 해당 노드를 `visibility:hidden` 상태에 가둔 채 복구하지 못하고 있음을 확인했다.
- 최초 가설이었던 `MiniBarChart`의 `notMerge`/bar-vs-line 차이는 라인 차트(Milvus)에서도 동일 현상이 재현되어 기각했다.
- 실제 원인: `Home.tsx`의 `flowNodesWithLiveTrend`가 5초마다 `sparklineData`를 가진 노드의 `data` 객체를 새로 생성했고, `PipelineFlowDiagram.tsx`의 `styleEdges`도 매 렌더마다 새 배열을 만들어 `<ReactFlow nodes/edges>`에 매번 새 identity가 들어갔다. React Flow는 identity가 바뀐 노드를 재측정하려 시도하지만 이 복구가 가끔 실패해 영구히 숨어버린다.

### 3. 수정 적용 및 검증

- `sparklineData` 재앵커링을 노드 배열에 얹지 않고 `AnchorContext`로 넘겨 `FlowNodeRenderer` 내부에서 로컬로 처리하도록 변경. `styleEdges`도 `useMemo`로 고정.
- 로컬 서버에서 5초 자동 갱신을 40초 이상 지켜보며 Adapter-CDC/Milvus/엣지가 더 이상 사라지지 않음을 확인. 콘솔 에러 없음, `tsc -b` 통과.
- 참고 파일: `src/components/flow/PipelineFlowDiagram/PipelineFlowDiagram.tsx`, `src/components/flow/PipelineFlowDiagram/PipelineFlowDiagram.types.ts`, `src/pages/Home.tsx`

## 🔧 주요 변경사항

| 변경 전 | 변경 후 | 이유 |
|---|---|---|
| `Home.tsx`가 `lastRefresh`마다 `sparklineData`를 가진 노드의 `data` 객체를 새로 만들어 `nodes` prop으로 전달 | 원본 `homeFlowNodes`(안정적 참조)를 그대로 전달하고, `anchor={lastRefresh.getTime()}`만 별도 prop으로 전달 | 노드 identity churn 제거 |

| `styleEdges = edges.map(...)` (매 렌더 재계산) | `useMemo(() => edges.map(...), [edges])` | edges identity churn 제거 |

## 🐛 발생한 문제 & 해결

### 문제 1: Adapter-CDC 박스가 레퍼런스 이미지보다 휑해 보임
- **원인**: `MiniBarChart`가 TopHeader `range`로 `sparklineData`를 직접 `.filter()`하는데, mock 데이터가 5분 간격 12포인트(총 55분 폭)라 기본 기간 "15m"에서는 2~3개 포인트만 남아 막대가 듬성듬성해짐.
- **해결**: 이건 버그가 아니라 mock 데이터 밀도와 필터링 구간의 불일치임을 확인하고, 우선순위가 더 높은 실제 소실 버그(문제 2) 조사로 넘어감. 데이터 밀도 조정은 `🔜 다음 작업`으로 이월.

### 문제 2: Adapter-CDC/Milvus 노드와 연결 엣지가 몇 초 뒤 완전히 사라짐 (새로고침하면 복구)
- **원인**: `Home.tsx`의 `flowNodesWithLiveTrend`가 5초 auto-refresh(`App.tsx:34`, `useAutoRefresh(autoRefresh, 5000)`)마다 `sparklineData`를 가진 노드의 `data` 객체를 새로 생성하고, `PipelineFlowDiagram.tsx`의 `styleEdges`도 매 렌더 새 배열을 만들어 React Flow(`@xyflow/react`)의 `nodes`/`edges` prop에 매번 새 identity가 유입됨. React Flow는 identity가 바뀐 노드를 `visibility:hidden` → 재측정 → `visible`로 복구하려 하는데, 이 복구가 가끔 실패해 노드가 영구히 숨겨진 채로 남음(`getComputedStyle`로 직접 확인).
- **해결**: `sparklineData` 재앵커링을 노드 배열이 아닌 Context(`AnchorContext`)로 전달해 `FlowNodeRenderer` 안에서만 처리하도록 변경, `styleEdges`도 `useMemo`로 고정해 `edges` prop이 실제로 바뀔 때만 재계산되게 함.
- **참고**: 최초 가설(`MiniBarChart`의 `notMerge`, bar vs line 차트 차이)은 라인 차트(Milvus)에서도 동일 현상이 재현되어 기각. `getComputedStyle` 반복 폴링 스크립트는 타이밍에 따라 신뢰할 수 없는 결과를 반환해서(같은 노드가 순간적으로 hidden/visible을 오갔다), 실제 판단은 여러 시점의 스크린샷으로 교차 검증했다.

## 💡 배운 점 / 메모
- 이 프로젝트의 `PipelineFlowDiagram`은 이미 한 번(`range`) 같은 클래스의 버그를 Context 우회로 고친 이력이 있음 — "노드/엣지 identity를 시간 기반 값으로 매번 새로 만들지 않는다"는 원칙을 새 기능 추가할 때마다 지켜야 재발하지 않는다.
- 겉보기 증상(bar chart, 특정 컴포넌트)만 보고 세운 첫 가설은 틀릴 수 있다 — 같은 조건에서 다른 변형(line chart)도 재현되는지 먼저 교차 확인하는 게 시간을 아낀다.
- `getComputedStyle` 같은 실시간 DOM 상태를 자동화 스크립트로 반복 폴링하면 타이밍/스로틀링 때문에 오독하기 쉽다 — 스크린샷 여러 장으로 교차 검증하는 편이 더 신뢰할 수 있었다.
