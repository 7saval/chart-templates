참고 파일: `src/components/flow/PipelineFlowNode/{PipelineFlowNode.tsx,.types.ts}`, `src/components/flow/PipelineFlowDiagram/PipelineFlowDiagram.tsx`, `src/mocks/home.mock.ts`, `src/pages/Home.tsx`

### 2. `AlertEventTable` / `StatusDataTable` 헤더 스타일 조정

두 컴포넌트가 공유하는 `src/components/ui/table.tsx` 프리미티브(현재 소비자가 이 둘뿐)를 직접 수정했다. `TableHeader`에 `bg-muted/40` 배경 틴트, `TableHead` 텍스트 색을 `text-foreground` → `text-muted-foreground`로 바꿔 값(`TableCell`, 기본 전경색)과 시각적으로 구분되게 했고, `TableRow`의 `hover:bg-muted/50`을 제거해 행 호버 하이라이트를 없앴다.

참고 파일: `src/components/ui/table.tsx`

### 3. Kafka 3-4 "Broker Cluster Topology" 노드 겹침 버그 수정

브라우저에서 실제 렌더링을 캡처해서 확인한 결과, broker-5 노드의 라벨+CPU/MEM/DISK 텍스트가 broker-2 노드 원과 겹쳐 읽을 수 없는 상태였다. 원인은 `TopologyDiagram.tsx`의 d3-force 시뮬레이션이 `link`/`charge`/`center` 세 힘만 쓰고 `forceCollide()`가 없어서 — 노드 원(r=24)보다 훨씬 넓은 라벨+배지 텍스트 영역까지는 서로 밀어내지 않았기 때문이다. `forceCollide(52)`를 추가하고, `Kafka.tsx`에서 `TopologyDiagram`에 기본값(320px) 대신 `height={380}`을 넘겨 5노드 × 텍스트 4줄이 들어갈 여유를 확보했다. 재로드 2회 + PPS/MinIO 8노드 토폴로지(같은 컴포넌트 공유)로 회귀 없음을 확인했다.

참고 파일: `src/components/topology/TopologyDiagram/TopologyDiagram.tsx`, `src/pages/Kafka.tsx`

### 4. Kafka 3-4 Producers↔Topic, Consumer Groups↔Sinks/Downstream 행 커넥터 구현

PPTX Kafka 슬라이드(`ppt/media/image2.png`)를 크롭해서 확인하니, 목업엔 Producers 리스트 각 행 → 점선 화살표 → Topic 리스트 같은 행, Consumer Groups 각 행 → 점선 화살표 → Sinks/Downstream 같은 행으로 연결돼 있었는데 실제 구현엔 리스트/테이블 사이를 잇는 커넥터 개념 자체가 없었다.

`RowConnector`(신규, `src/components/misc/RowConnector/`)를 만들어 `RankedList`의 행 리듬(`text-sm` 20px 높이 + `space-y-1.5` 6px 간격)에 맞춰 점선 화살표 N개를 렌더링하도록 했다. `Kafka.tsx`의 3-4 섹션을 재배치했다:

- `Producers` ↔ `RowConnector` ↔ `Topic`(신규 컴팩트 미리보기, `kafkaTopicsRanked`) — 한 행
- 기존 전체 컬럼 `Topics` `StatusDataTable`은 그대로 별도 패널로 유지(정보 손실 없음)
- `Cluster Summary`는 Producers 옆자리에서 빠져 `Broker Cluster Topology` 패널 상단 스탯 바로 이동(목업과 동일한 배치)
- `Consumer Groups (by Lag)` ↔ `RowConnector` ↔ `Sinks / Downstream` — 한 행

참고 파일: `src/components/misc/RowConnector/{RowConnector.tsx,.types.ts,.stories.tsx,index.ts}`, `src/mocks/kafka.mock.ts`, `src/pages/Kafka.tsx`

## 🐛 발생한 문제 & 해결

### 문제 1: `TopologyDiagram` 노드/라벨 겹침
- **원인**: d3-force 시뮬레이션이 노드 원(r=24) 중심 간 반발력만 계산하고, 원 아래로 확장되는 라벨+배지 텍스트(약 78px)까지는 충돌 방지 대상에 포함하지 않았음. 여기에 기본 캔버스(480×320)가 5노드×텍스트 4줄을 담기엔 좁았던 것도 원인.
- **해결**: `forceCollide(52)`(텍스트 영역까지 고려한 반지름) 추가 + Kafka 페이지 호출부에 `height={380}` 지정.
- **참고**: 같은 컴포넌트를 쓰는 PPS/MinIO 8노드 토폴로지에서도 회귀 없음을 확인.

### 문제 2: `RowConnector`를 `RankedList` ↔ `StatusDataTable` 사이에 놓으면 정렬이 깨짐
- **원인**: `StatusDataTable`은 자체 컬럼 헤더 행(`h-10`, 40px)이 있고 `RankedList`는 없어서, 두 컴포넌트를 나란히 두면 첫 데이터 행의 시작 y좌표가 서로 달라 화살표가 행 중앙을 못 맞춤.
- **해결**: 픽셀 단위로 오프셋을 맞추려 하지 않고, Topic 미리보기도 `kafkaTopicRows`에서 과생한 `kafkaTopicsRanked`(label+value+status)로 만들어 `RankedList`로 통일 — 같은 컴포넌트라 행 높이가 원천적으로 동일해짐. 전체 컬럼 정보는 기존 `Topics` `StatusDataTable` 패널에 그대로 남겨 정보 손실 없이 해결.
- **참고**: `RowConnector` 자체는 `RankedList`의 행 리듬(`text-sm` 20px + `space-y-1.5` 6px)을 그대로 복제해서 만들었기 때문에, 항상 `RankedList` ↔ `RankedList` 사이에서만 쓰는 게 안전하다 — 다음에 이 패턴을 재사용할 땐 이 전제를 지켜야 함.
